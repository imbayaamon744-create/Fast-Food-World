# Stage 1 API contract

Endpoints use JSON under `/api`. Money is integer **KES minor units**: `5000` = KSh 50.00. IDs are UUIDs, enum values are uppercase, and unknown body fields are rejected. No customer accounts or payment APIs exist.

## CSRF and sessions

1. `GET /api/csrf` returns `{ csrfToken }` and an anonymous session cookie.
2. Every POST/PATCH needs `Content-Type: application/json`, `X-CSRF-Token`, the same cookie, and an `Origin` equal to `APP_ORIGIN`.
3. Browsers on the application origin send Origin/cookies automatically; use `credentials: "same-origin"`. REST clients must retain cookies and explicitly send Origin.
4. Login rotates the session and returns a new CSRF token. Logout destroys it; get a new anonymous token if needed.

No cross-origin access is enabled. A CSRF token is not a database/application secret.

## Public reads

| Method/path | Result |
| --- | --- |
| GET /menu | `{ currency, items }`, with category and availability |
| GET /menu?search=beef&category=samosas&available=true | Case-insensitive name/description search, category slug and optional availability filter |
| GET /categories | `{ categories }`, ordered for display |
| GET /settings | `{ settings }`, public details, ordering switches and delivery fee |
| GET /health | Database connectivity without connection details |

Unfiltered menus include unavailable items so clients can disable their Add buttons.
Items include `id`, `slug`, `name`, `description`, `priceMinor`, `available`, nullable `imageUrl`, `categoryId` and `category`.

## Quote, review and submit

`POST /orders/quote` accepts:

```json
{
  "items": [{ "menuItemId": "<UUID from menu API>", "quantity": 2 }],
  "fulfilment": "PICKUP"
}
```

Response: `{ quote: { currency, fulfilment, items, subtotalMinor, deliveryFeeMinor, totalMinor } }`.
Lines include database names, quantities, unit prices and line totals. Review this quote before submission. A quote does not create an order or reserve stock.

`POST /orders` needs an **Idempotency-Key** header containing a fresh random UUID, generated by `crypto.randomUUID()`. Body:

```json
{
  "customerName": "Guest Name",
  "phone": "0712345678",
  "items": [{ "menuItemId": "<UUID from menu API>", "quantity": 2 }],
  "fulfilment": "DELIVERY",
  "deliveryAddress": "Building, street and directions",
  "notes": "Optional instructions",
  "expectedTotalMinor": 25000
}
```

For pickup, omit `deliveryAddress`. Set `expectedTotalMinor` from the reviewed quote, not the illustrative amount above.
Quantities are integers 1–20; use one line per item and at most 50 distinct items.

A new submission returns **201** `{ order, trackingToken, replayed: false }`.
An exact retry returns **200**, the same order/token and `replayed: true`.
Changed details with the same key return **409 IDEMPOTENCY_CONFLICT**.
After an uncertain network response, retain and resend the original key/payload. Generate a new key for a genuinely new order.

The server recalculates prices/fees in a serializable transaction. Unavailable items or closed fulfilment return 409. A different total returns **409 PRICE_CHANGED**: obtain and review a new quote. Item names/prices are stored as immutable snapshots. Order, lines and initial ACCEPTED history are atomic. Valid ordinary orders are confirmed immediately without admin approval.

### Private tracking

`POST /orders/track` accepts `{ "token": "<trackingToken>" }` and returns `{ order }`. Unknown tokens return 404.
There is no public lookup by phone or order UUID.
Tracking includes items, totals, status and public history; contact/address, notes, admin identity and stored hashes are omitted.

The frontend uses a URL fragment for private tracking links. Never put tokens in query parameters. Anyone holding one can see that order's tracking details. There is no account recovery flow.

## Catering

`POST /catering` needs a random UUID **Idempotency-Key** and accepts:

```json
{
  "customerName": "Guest Name",
  "phone": "0712345678",
  "eventDate": "2099-12-01",
  "location": "Event venue",
  "guestCount": 30,
  "package": "Classic",
  "eventDetails": "Optional preferences"
}
```

Use a real date today or in the future in **Africa/Nairobi**. Packages: `Classic`, `Premium`, `Deluxe`. Guest count: 1–10000.
Response: **201** `{ request: { id, status: "PENDING", createdAt }, message, replayed: false }`.
Exact retries return 200; changed details with the same key return 409.

The receipt explicitly says **this is not a confirmed booking**. Availability, menu and price need restaurant follow-up.

## Admin authentication

- `POST /admin/login`: `{ email, password }` -> `{ admin: { id, email }, csrfToken }`.
- `GET /admin/session`: authenticated administrator or 401.
- `POST /admin/logout`: send `{}`; returns 204 and destroys the session.
- Create admins only through `npm run admin:create -- --email ...`.
- Login errors do not reveal whether an account exists. Password hashes never appear in responses.
- All other `/admin/*` endpoints require an active administrator and unexpired authentication, plus CSRF on mutations.

## Admin management

| Method/path | Input and behaviour |
| --- | --- |
| GET /admin/orders/summary | All-time status counts and summed order values; not payment/revenue reporting |
| GET /admin/categories | All categories for management |
| GET /admin/orders | `page=1&pageSize=20&status=ACCEPTED`; page size max 50; orders and total |
| GET /admin/orders/:id | Contact/fulfilment details, items and status history |
| PATCH /admin/orders/:id/status | `{ expectedStatus, status, reason? }`; cancellation requires a reason; atomic transition and audit history |
| GET /admin/menu | All menu items |
| POST /admin/menu | `{ slug, name, description, priceMinor, categoryId, available?, imageUrl?, sortOrder? }` |
| PATCH /admin/menu/:id | Nonempty subset of menu fields |
| POST /admin/categories | `{ slug, name, sortOrder? }` |
| PATCH /admin/categories/:id | Nonempty subset of category fields |
| PATCH /admin/settings | Nonempty subset of name, address, phone, email, openingHours, deliveryFeeMinor, acceptingOrders, pickupEnabled, deliveryEnabled |
| GET /admin/catering | `page=1&pageSize=20&status=PENDING`; requests and total |
| PATCH /admin/catering/:id | `{ expectedStatus, status, adminNotes?, quoteMinor? }` |

Slugs use lowercase letters, digits and single hyphens. Prices/fees are 0–1000000 minor units.
Images may be `null`, HTTPS URLs or relative `images/...` references without traversal. No image upload or fetch proxy is provided.
Mark items unavailable instead of deleting them; historical order relationships remain.
Phone/email settings may be `null`; currency is KES and timezone is Africa/Nairobi.
Read settings/categories through their shared public endpoints.

Valid order transitions:

```text
ACCEPTED -> PREPARING -> READY
PICKUP:   READY -> COMPLETED
DELIVERY: READY -> OUT_FOR_DELIVERY -> COMPLETED
Any nonterminal state -> CANCELLED (requires reason, 1–1000 trimmed characters, visible in tracking)
Legacy PENDING -> CANCELLED only; no automatic acceptance or approval action
COMPLETED and CANCELLED are terminal.
```

Send the status currently displayed as `expectedStatus`. Concurrent changes return 409 rather than overwriting each other.
Catering: `PENDING -> CONFIRMED` or `PENDING -> DECLINED`, through authenticated admin endpoints only. Submitting a request or saving a quote never confirms a booking. Legacy REQUESTED/CONTACTED may receive an explicit CONFIRMED/DECLINED decision; legacy CLOSED remains closed without inferring an outcome.
Same-status updates may edit notes and quotes. quoteMinor is nullable, integer KES minor units from 0–1000000000; null clears it. Quotes and internal notes are admin-only. No automated messages are sent. Confirmed/declined decisions cannot reopen or switch. Legacy closed requests cannot reopen. Existing statuses and history remain intact; no data backfill runs.

## Errors and limits

Errors: `{ error: { code, message, fields?, requestId? } }`. Validation fields include paths/messages, not submitted values.

| Status | Meaning |
| --- | --- |
| 400 | Invalid fields/JSON/reference |
| 401 | Missing/expired admin authentication or invalid login |
| 403 | CSRF or Origin rejected |
| 404 | Resource/private tracking token not found |
| 409 | Stale quote/status, unavailable item/fulfilment, duplicate slug or idempotency conflict |
| 413 / 415 | Body exceeds 32 KB / mutation is not JSON |
| 429 | Rate limited; respect Retry-After (seconds) |
| 500 / 503 | Request failed / setup incomplete |

Database counters enforce: 300 API requests/minute/IP; 60 quotes/minute/IP; 20 submissions/15 minutes/IP; 60 tracking attempts/15 minutes/IP; 10 catering requests/hour/IP; 10 login attempts/15 minutes per IP and per normalized email.
Fixed windows protect against abuse; retries count toward limits.
